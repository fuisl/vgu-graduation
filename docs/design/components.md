# Component Foundations

The shared UI package begins deliberately small. Components earn their place through reuse. Live showcase of the brand primitives, site shell and guest chip: `/design-system`.

## Brand primitives

Exported from `@grad/ui` (`packages/ui/src`), styled in `packages/design-tokens/src/brand.css` under `[data-theme="brand"]`, brand tokens only. Render them inside `BrandTheme`.

### `BrandTheme`
Root of the theme: `<div data-theme="brand">`. Every guest-facing route wraps its page in it. Admin and docs do not.

### `Section`
Full-bleed band. Content sits in `.brand-section-inner`, capped at 1600px (`--brand-content`). Text colours follow the tone.
- `tone`: `"blue"` (hero, feature bands, calls to action), `"white"` (reading, forms, lists) or `"blue-deep"` (the footer band).
- `density`: `"airy"` (default, about 6rem desktop / 4rem mobile) or `"compact"` (about 3rem / 2rem) for forms, the invitation, RSVP, the gallery and the footer.
- `narrow`: a reading-width inner column, for forms and short text.
- `id`, `aria-labelledby`: label the landmark by its heading.

Pages alternate blue and white bands. Do not nest a `Section` in a `Section`.

### `BrandEyebrow`
Mono uppercase label. Colour follows the surrounding tone. `ellipsis` appends ` ...`. It has no built-in bottom margin; the layout spaces it. Use one above a section heading or for a metadata line ("When", "Venue and time").

### `Cta`
The call to action. `tone` is the surface it sits on: `"on-blue"` renders a white box, `"on-white"` a blue box.
- `variant="primary"` (default): filled box with an arrow tile (`ArrowUpRightPixel`). One per view.
- `variant="secondary"`: outlined (transparent fill, 1px border, text follows the surface), 44px minimum, no tile. For supporting actions such as "Back to gallery", "Close" and calendar options.
- `href` renders an anchor, otherwise a button (`type`, `onClick`). `aria-label` names icon-only labels. `tabIndex` is passed through.
- `external` (with `href`): `target="_blank" rel="noopener noreferrer"`, a visually hidden "(opens in a new tab)" and the arrow (also on secondary).
- `icon`: replaces the arrow in the tile. The only other icon is `PaperPlanePixel`, for send actions.
- `disabled`: outlined and muted on both variants. A disabled link renders without `href` and with `aria-disabled="true"`.

### `PillGroup`, `PillItem`, `PillToggle`
Segmented control. `tone` is the surface: `"on-blue"` (default) is a deep-blue container with a white active pill; `"on-white"` is a soft-blue container with a solid blue active pill.
- Navigation (default): `<PillGroup label>` renders a `nav`; `PillItem` links take `current` (`aria-current="page"`).
- Toggle: `<PillGroup as="toggle" label>` renders a `role="group"`; `PillToggle` buttons take `pressed` (`aria-pressed`) and `onClick`. It wraps on narrow screens. Give a `PillToggle` an `aria-label` when its text is a single letter.

The gallery filters, card size and layout, and the `/ascii-live` character set are `on-white` toggles. The site header navigation is the only `on-blue` navigation.

### `ArrowUpRightPixel`
Pixel-style up-right arrow on a 7x7 grid, decorative (`aria-hidden`). Used by `Cta` and the signed-in guest chip; rarely needed directly.

### `PaperPlanePixel`
Pixel-style paper plane for send actions, decorative (`aria-hidden`): the "send" icon from [pixelarticons](https://pixelarticons.com) (MIT). Pass it to `Cta`'s `icon`. It is drawn 1.25em because its pixels are finer than the arrow's. Do not add other icons to `Cta` without design review.

## Site shell (`apps/web/app/site`)

App-level, not in `@grad/ui`. Every brand page renders `<SiteHeader i18n={i18n} current="…" />` first and `<SiteFooter i18n={i18n} />` last, inside `BrandTheme`, with `i18n` from `await getI18n()` (#9); every label in the shell comes from the dictionaries (`languages.md`).

- **`SiteHeader`**: the menubar, the single home of what every page needs (owner brief, 2026-10: "put it in the menubar"). Sticky with a fill when scrolled, 72px high (#78). At the top of the page it is unfilled and the first band runs up behind it (the band grows a 72px transparent top border); once stuck it is filled solid with the colour of the band under the top edge and a 1px hairline below (`--brand-line-on-blue` or `-on-white`), so text never shows through behind the logo or Menu. A zero-height sentinel before the header tells `ThemeColorSync` when it is stuck (IntersectionObserver); only paint changes, never layout, and the colour change is instant under reduced motion. Before the sentinel, the skip link is the first focusable element: "Skip to content" (`shell.skipToContent`), off-screen until focused, then a white 44px tag at the top left; it points at `#main` (give the page's `<main>` `id="main"`) and, with JavaScript, focuses any `<main>`. Admin has the same link in its neutral style. Desktop, left to right: the compact "F" mark (`BrandLogo variant="compact"`, in an on-blue and an on-white copy; CSS shows the one that matches the band under the header), a link to `/` named "Home" (there is no Home pill); one `PillGroup` labelled "Main" (44px pills) holding the **event essentials** (`EventEssentials`: the short date and the venue name, "20 Nov · Ceremony Hall", linking to `/venue`; screen readers also hear ", venue and calendar"), then **Camera** (`/gallery`, which opens the shared camera) and **Wishes** (`SITE_NAV` in `nav.ts`); then the action row: EN | VI, text size (`TextSizeControl variant="compact"`) and the `action` slot, which defaults to `GuestChip`. The essentials read `GET /event` (cached 300 s, shared with the page) inside a `Suspense` boundary whose fallback is a plain "Venue" label, so the header never waits on the API and a failed call degrades to that label. When space runs out (961px with the largest text) only the essentials pill shrinks: the venue name ellipsizes; the full name stays in the accessible name. `current` (`"home" | "venue" | "gallery" | "wishes"`) marks the active page; `home` marks nothing. It is a server component; the sheet, chip, language and text size controls are the client code.
- **`MobileMenu`**: at 960px and below the bar shows the mark, a one-tap **Camera** link (a 44px bordered box with the word, like Menu; a shortcut, so it never carries `aria-current`) and an icon "Menu" button (Octicons three-bars, a 44px square, `aria-label` "Menu"). Menu opens a full-screen blue dialog (`role="dialog"`, `aria-modal`): the "F" mark and an icon "Close" button (Octicons x); the essentials as the first link (mono "When and where", the full date large, the time and venue under it; links to `/venue`); Camera and Wishes as large rows (the current one in the accent colour); then, within thumb reach, the guest chip and the two settings, Language and Text size, under visible mono labels (hidden from assistive technology; the groups carry the names). Escape or Close returns focus to the Menu button, focus is trapped inside the sheet, body scroll is locked while open, and it closes when the viewport grows past 960px or a link is chosen. `MenuSheetPreview` renders the same sheet body as a static, `inert` picture for `/design-system` (#153).
- **`LanguageSwitch`** (#9): the EN | VI switch, a small mono pill (deep-blue container, the current option filled white; on a white backdrop the header flips it to soft blue with a blue current option). Desktop: in the action row before text size and the guest chip. Mobile: in the sheet, under the guest chip. Footer: in the meta row, the one that works on a phone without JavaScript (the sheet needs it). It is a form of two submit buttons posting `lang` and the current path (`usePathname`, server-rendered) to `POST /api/locale`, which sets the `lang` cookie and redirects back with a 303. Each option is a 44px target named by its visible code and then its language in that language (`aria-label="EN, English"` / `"VI, Tiếng Việt"` with `lang`, so the name starts with the visible text, WCAG 2.5.3), the group is labelled "Language", and the current option has `aria-current="true"`. No flags.
- **`GuestChip`**: the two-state right-hand pill. Signed out: a `Cta` "My invitation" (`header.invitation`) to `/me` (`SignedOutChip` in `SiteAction.tsx`), which explains how to open an invitation. Signed in: `SignedInChip`, a pill with the guest's blobatar, given name (at most 12ch, then an ellipsis; the whole given name stays in the link's accessible name) and the arrow tile, linking to the guest profile `/me` (#139), which links on to the invitation. It renders signed out on the server and until `GET /api/me` answers, so there is no layout shift and the page never waits on it. `/api/me` reads the `HttpOnly` invitation cookie server-side and returns only `{signedIn, givenName, avatarSeed}` (the seed is the guest id, never the token), always with status 200 and `Cache-Control: private, no-store`. `givenName` is the guest's `givenName` from `GET /invitations/me` (#170), so "Nguyễn Văn An" shows "An" and "John Smith" shows "John".
- **`GuestAvatar`** (`guest-avatar/`): the animated blobatar (`@blobatar/react`). Pass a stable non-secret `seed`; pass `label` only when no visible name sits beside it. Eyes follow the pointer (see `motion.md`); `followTouch` (the large profile avatar only) also follows the last touch on phones (`touch-gaze.ts`). The idle animation pauses while the tab is hidden. **`StillAvatar`** is the same face as a static `<img>` with no motion code, for small faces in lists (who invited the guest).
- **`SiteFooter`**: minimal, and it does not repeat the menubar (2026-10). A `Section tone="blue-deep" density="compact"` band: the full wordmark (`BrandLogo variant="full"`, the only place it appears); a "Footer" nav with only what the header does not hold, **Memories** (`/memories`, the curated archive), **Accessibility** (`/accessibility`, #176) and **Credits** (`/about`, #7); and a meta row with "VGU graduation · Class of 2026" and the EN | VI switch (the no-JavaScript fallback). The "Grad '26" label is gone.
- **`TextSizeControl`** (`text-size/`): Default, Large and Largest (#176). It sets `data-text-size` on `<html>`, which `globals.css` maps to a root font size of 100%, 118.75% or 137.5%; every brand size is in rem, so type, spacing and controls scale together, and fixed-pixel chrome (the 72px header, 44px targets) stays put. The choice is remembered per device in `localStorage` (`grad26.textSize`) and applied before first paint by an inline script in the root layout; copies on one page stay in step by watching the attribute. It lives in the menubar as `variant="compact"`: three "A"s in rising sizes on the EN | VI pill style, each named by its word ("Default", "Large", "Largest") with `aria-pressed`; no option is pressed until mount, because the server cannot know the stored choice. `variant="full"` (a toggle `PillGroup` with the words) remains for any page that explains the setting. Checked at 360px on every brand page at the largest step: no horizontal scroll. No overlay widget (`anti-patterns.md`).

## Guest pages (`/me`, `/guide`, `/accessibility`)

- **`/me`, the guest portal (#139):** the guest's **name badge** is the hero (`NameBadge` in a `BadgeStage`, `app/guest/badge/`, see `landing.md`, "Name badge"): a lanyard name tag printed with the given name large, the full name below when it differs, "Guest", the date, the campus and the pass QR, which drops in and can be dragged. Beside it (below it on phones) only an eyebrow, where the guest stands (the RSVP summary) and the **one next action**: "Respond to your invitation" (`/invite#rsvp`) before an answer; once attending, "Add to calendar" (`AddToCalendar show="action"`) with "Change your RSVP" secondary; after declining, "Change your RSVP". Then "Invited by" (still avatars) on one line. The page heading is visually hidden; the badge is the visual title. A white compact band, "Your day", holds title-only rows (`LinkRows`) for what the site menu does not have: the guide-book and "Save badge" (the pass QR as an SVG, once the pass has loaded). No event facts, text size or nav links: the menu has them. Signed out, the hero is the unnamed demo badge with "Open your invitation" and the steps below (`/invite` without a cookie shows a "missing" notice linking here); a revoked, expired or unreachable invitation gets the matching notice (`GuestNotice`, the portal's blobatar instead of a badge, as on `/guide`). Personal, so `noindex` and `no-referrer`.
- **`/invite`, the invitation:** a blue greeting band ("You are invited, {name}", who invited them), then one compact narrow white band (`id="rsvp"`) where the RSVP form is the only primary action; its intro says who the invitation covers, and once answered the saved answer sits under the heading. Below it, "Ceremony details" is a closed disclosure (the `invite-assist` style) holding `EventDetails` (when, the calendar options, where with directions, live captions, arrival), and two `LinkRows`: the name badge (`/me`) and the guide-book. Notices (missing, invalid, expired, error) are one blue band with the reason and one action or the organizer contact; the page stays blue to the footer.
- **`/guide`, the guide-book (#140):** linked from the profile and the invitation, not the menubar. A blue band says who tailored it (the inviting graduates) or that these are the defaults; the white band has category filter pills (`PillGroup as="toggle" tone="on-white"`, only categories with items) and one card per place with category, title, description, time hint and an "Open in Maps" secondary `Cta` (external). Filtering is client-side, so a loaded page keeps working offline; the BFF revalidates the guide every 300s and serves the cached copy while the API is unreachable. Loading, empty, error and signed-out states.
- **`AddToCalendar`** (`app/calendar/`): the one calendar block on `/venue`, `/invite` and `/me`. The action ("Add to calendar") opens Google Calendar on Android, the `webcal` feed on Apple devices and the `.ics` file elsewhere (and in the server render). The options are Google, Apple, Outlook and .ics as secondary `Cta`s. `show="action"` renders the action alone on `/me` once the guest is attending; `show="options"` is unused since the 2026-10 landing pass; `emphasis="secondary"` where the RSVP is primary.
- **`/accessibility` (#176):** venue access, live captions, how to ask for help, the organizer contact from `GET /event`, and one line on the site itself that points to text size in the menu (the control is no longer repeated there). Venue facts are drafts (`TODO(owner)`).
- **`BrandLogo`** (`logo/BrandLogo.tsx`): the Fuisloy pixel logo. `variant="full" | "compact"`, `tone="on-blue" | "on-white"` names the surface it sits on (the on-blue files turn the dark blocks white). Size it from the parent.

## Legacy primitives

Kept for admin and non-brand pages; not for brand pages. `/design-system` shows all four in a neutral panel (#144).
- `Container`: horizontal gutter and max-width behaviour (`--wide`). Brand sections use `Section`'s inner width instead.
- `Eyebrow`: neutral mono label (use `BrandEyebrow` on brand pages).
- `Rule`: structural divider.
- `Button`: solid and outline actions with a minimum 44px target (use `Cta` on brand pages).

## Rules
Prefer composition over card proliferation. Components expose semantic variants, not arbitrary styling knobs. Product-specific behaviour stays outside primitives. Every interactive primitive must remain keyboard-accessible and respect reduced motion. A new primitive needs design review (`docs/design/llm-reference.md`).

### Browser UI colour (`ThemeColorSync`)

`SiteHeader` renders `<meta name="theme-color" content="#1F4BB0">` (React hoists it into `<head>`) and `ThemeColorSync`, which keeps the browser's toolbar tinted like the section under the top edge while scrolling. It also fills the header once it is stuck (`data-stuck`, `--brand-header-fill`, see `SiteHeader`) and, while stuck, flips the logo, nav, action and Menu button together to match the fill. It reads the background of the first opaque element at the viewport's top edge (skipping the header itself), at most once per frame and only when it changes, and writes it to the meta tag (Chrome on Android, Safari 15–18) and to `body.style.backgroundColor` inline (Safari 26 ignores `theme-color` and tints from the page, re-reading only inline body styles). Both are reset when a brand page unmounts, so admin and docs keep their own colours. Nothing to do per page: any page with `SiteHeader` gets it.
